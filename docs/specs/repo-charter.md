# Repository Charter

日期：2026-04-14
状态：active

## 使命

把本仓库建设为“新项目启动时的 harness 方法参考库”，使用户和未来团队在开始任何软件开发、模型训练、算法工程或数据工程项目时，都能先从这里选择合适的 harness 方法，再进入实现阶段。

## 成功标准

本仓库应该能够支持：
- 用统一入口选择项目类型
- 为新项目提供可落地的控制面设计
- 说明 Hermes 如何作为默认 runtime 使用 harness
- 同时保持方法对其他 runtime 可迁移
- 当遇到未覆盖的新项目类型时，快速补齐新 playbook
- 通过最小机械检查防止文档漂移

## 非目标

- 不把本仓库写成单一 agent 的产品说明书
- 不把本仓库限制为某一个代码仓库的私有操作笔记
- 不在没有项目类型分类的情况下直接生成一大段泛化建议

## 核心约束

1. 仓库是 source of truth
2. Hermes 是默认 runtime，但不是唯一 runtime
3. 新项目类型缺失时，必须补仓库工件，而不是仅靠会话解释
4. 方法更新要同步反映在目录、playbook、runbook 和检查中
