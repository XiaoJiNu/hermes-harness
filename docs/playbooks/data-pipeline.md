# Data Pipeline Harness Playbook

## 适用范围

适用于：
- ETL / ELT
- 数据抓取、清洗、索引、转换、批处理
- 数据质量治理和定时任务项目

## 核心目标

让 agent 对“输入契约、阶段划分、输出契约、质量门、调度与回放”有清晰约束，而不是只会写脚本。

## 最小控制面

至少应有：
- 输入数据契约
- pipeline stage 说明
- 失败处理 runbook
- 数据质量检查
- 回放 / 重跑规则
- 调度与运行登记方式

## 标准启动流程

1. 明确输入契约
   - 数据来源
   - 刷新频率
   - 字段与质量要求

2. 拆阶段
   - ingest
   - normalize
   - validate
   - publish

3. 为每个阶段定义可验证产物
   - 输出目录
   - 行数/主键/分布/去重等检查

4. 先做最小端到端 batch
   - 先小数据量打通
   - 再扩到正式调度

5. 建立异常与重跑流程
   - 哪些错误可重试
   - 哪些错误必须人工介入

## Hermes 的默认工作方式

- 先读数据契约和 stage 说明
- 先写或更新 plan
- 先做最小批次，不直接全量跑
- 报告结果时附带质量检查结论

## 可替换 runtime

Hermes 之外，任何能执行仓库命令、调度脚本、读取日志和更新文档的 runtime 都可以。

## 常见反模式

- 只有脚本，没有输入输出契约
- 直接跑全量，跳过 sample / smoke
- 结果只有日志，没有结构化质量结论
- 数据口径变化了，但未更新 runbook 和目录
